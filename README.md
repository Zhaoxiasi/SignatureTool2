# SignatureTool2 功能与配置说明文档

本项目在原有编译、签名、打包流水线的基础上，扩展了进程级运行控制、严格目录同步、压缩包命名模板化、打包后处理（签名校验/本地复制/FTP上传）、微软商店 (MSI) 自动化构建，以及代码混淆防呆校验。

---

## 一、向后兼容设计原则

所有新增配置项均遵循 **“默认安全、留空等同旧版”** 的设计原则：
- 旧配置文件（`config.plist`）无需手动修改，加载时缺失的新增字段均回退到安全的默认值。
- 所有新增字段（同步模式、压缩包模板、MSI 配置、打包后配置、混淆工程等）在界面中留空或不勾选时，流程严格按照旧版原有逻辑执行，不会产生多余弹窗、多余清理或误报错。

---

## 二、新增配置项及使用规则

### 1. 同步模式 (SyncMode)
位于主界面配置面板 **“同步模式”** 下拉框：

| 模式 | 规则与行为 | 适用场景 |
| :--- | :--- | :--- |
| **增量**（默认） | 仅对比文件修改时间，只拷贝比上次签名时间 (`LastSignTime`) 新的文件。不清理目标目录。 | 日常快速增量打包。 |
| **严格同步** | 1. 全量拷贝源目录的所有待签名文件；<br>2. 预检目标目录，找出在源目录中**已不存在**的陈旧冗余文件；<br>3. 弹出 `SyncCleanDialog` 勾选框，列出所有多余文件供人工确认；<br>4. 确认后删除未勾选保留的文件，并递归清理多余空目录。 | 发布正式版本、清理旧废弃 DLL/资源文件时。 |

> [!NOTE]
> 在“严格同步”弹窗中，若用户点击“取消”，则系统仅跳过该项的本次签名，不会中断其他项目的处理。

---

### 2. 压缩包命名模板 (FileNameTemplate / 全局 NameTemplate)

配置位置：
- **单项配置**：单项配置面板中的 **“压缩包名”** 文本框。
- **全局配置**：主界面底部的 **“默认模板”** 文本框（持久化到全局配置 `Package_NameTemplate`）。

#### 占位符支持：
- `{Name}`：当前项的软件名称（`SoftwareName`）。
- `{Company}`：当前项关联的公司名称（`Company`）。
- `{yyyyMMdd}`、`{yyyy-MM-dd}`、`{HHmm}` 等：支持所有 .NET 标准 DateTime 格式化占位符。

#### 命名解析规则（优先级从高到低）：
1. 若单项 **“压缩包名”** 非空，按单项模板解析生成包名。
2. 若单项为空，但全局 **“默认模板”** 非空，按全局模板解析生成。
3. 若单项与全局**均留空**（即完全兼容旧配置）：
   - 若目标目录名包含 `custom`，严格沿用旧版规则将 `custom` 替换为 `yyyyMMdd.7z` / `yyyyMMdd.zip`；
   - 若不包含 `custom`，自动回退使用 `{Name}_{yyyyMMdd}`。

### 3. 打包后处理配置 (PostActions)

点击单项中的 **“后处理配置...”** 按钮即可打开专属配置弹窗：

#### (1) 校验全签名 (`VerifySign`)
- **说明**：勾选后，在生成 7z/Zip 压缩包之后，自动调用 `signtool.exe verify /v` 递归遍历目标目录。
- **校验项**：
  1. 所有支持签名的文件类型是否均包含有效数字签名；
  2. 是否已包含时间戳信息（避免因未加时间戳导致证书过期后校验失败）。
- **校验结果**：在日志面板输出通过或未签名的文件清单。

#### (2) 本地拷贝 (`CopyTargets`)
- **说明**：多行文本框，每行配置一个本地/局域网共享目录路径（例如 `D:\Releases` 或 `\\192.168.1.100\Shared\Builds`）。
- **行为**：压缩打包完成后，自动将生成的 `.7z` / `.zip` 压缩包复制到各个指定目录。目录不存在时会自动创建。
- **规则**：留空时自动忽略。

#### (3) FTP 上传 (`FtpTargets`)
- **说明**：多行文本框，每行配置一个 FTP 目标地址。
- **格式支持**：
  - 带鉴权：`ftp://username:password@ftp.example.com/releases/`
  - 匿名：`ftp://ftp.example.com/releases/`
- **行为**：压缩打包完成后，自动将压缩包以二进制被动模式上传至 FTP 服务器；请求超时为 60 秒。
- **规则**：留空时自动忽略。

### 4. 微软商店打包 (PackageMsi - Advanced Installer)

勾选单项中的 **“打包微软商店（msi）”** 即可展开 MSI 自动化配置：

| 配置项 | 字段名 | 说明与要求 |
| :--- | :--- | :--- |
| **版本号** | `MsiVersion` | 写入 AIP 工程的版本号（如 `1.2.3`）。留空则跳过设置版本步骤。 |
| **Msi源文件夹** | `MsiSourcePath` | AIP 打包使用的输入源目录。同步时会将目标目录内容完全镜像复制覆盖到此，并清除源目录没有的多余文件；**但会自动保留根目录下的 `track.txt` 追踪文件**。 |
| **AIP工程路径** | `MsiAipPath` | Advanced Installer 工程文件（`*.aip`）的完整路径。 |
| **AI工具路径** | `MsiToolPath` | `AdvancedInstaller.com` 控制台程序路径（通常在 Advanced Installer 安装目录 `bin\x86` 下）。 |

#### 执行流程与防呆：
1. 压缩包生成后，系统将检查上述配置是否存在；
2. 执行目标目录到 `MsiSourcePath` 的镜像同步（保留 `track.txt`）；
3. 调用 `AdvancedInstaller.com /edit "<AipPath>" /SetVersion <Version>`；
4. 调用 `AdvancedInstaller.com /build "<AipPath>"` 执行默认构建。
5. **未勾选此项时，完全不执行任何 MSI 操作，不产生额外开销**。

### 5. 代码保护 / 混淆防呆与校验机制

在项目勾选并执行打包时：
1. **配置有效性检查**：
   - 只有当 `ProtecterID` 与 `ProtectProject`（混淆工程路径）**均非空**且文件真实存在时才会执行混淆；
   - 任一项留空或未配置时，视为不启用混淆，静默跳过，绝不误报错；
   - 若工程文件或混淆器可执行文件缺失，弹窗提示用户确认是否忽略混淆继续后续签名流程。
2. **进程退出码校验**：不再单纯匹配特定字符，而是基于 `ExitCode == 0` 判断混淆器执行结果。
3. **`*_Secure` 产物递归比对与人工核对**：
   - 混淆前自动清理历史残留的 `*_Secure` 目录，防止假阳性；
   - 递归扫描 `*_Secure` 目录生成文件清单，自动计算并显示与原文件的大小变化；
   - 弹出可滚动可复制的 `MessageDialog` 供开发核对，点击【是】后执行替换并清理 `*_Secure` 临时目录；点击【否】则安全终止流程。

---

### 6. 全局运行控制与一键终止 (RunControl)

- **停止按钮**：打包过程中遮罩层中央提供 **“停止”** 按钮。
- **强杀机制**：点击“停止”后，通过 `RunControl` 广播 `CancellationToken`，并对已追踪的外部命令进程（MSBuild、signtool、7z、AdvancedInstaller）调用 `taskkill /T /F` 强制结束完整进程树，杜绝后台残留或控制台缓冲区写满造成的界面死锁。
- **状态提示**：左侧列表项名称右侧会实时呈现状态后缀，例如 `软件名（签名成功）`、`软件名（构建失败）`、`软件名（已停止）`。

## 三、排错与日志

所有关键动作（构建、混淆、严格清理、签名校验、本地拷贝、FTP上传、MSI打包）均在右下角日志面板及 `Trace` 日志中完整输出。如遇异常可复制日志面板中的错误堆栈排查。
